# Frontend handoff: review API v1

Canonical schema: `openapi.yaml`, generated by `python -m scripts.export_contract` from Pydantic response/request models. Use this backend entrypoint: `uvicorn backend.app.main:app --host 127.0.0.1 --port 8000`. The earlier `membrane.app:app` demo is preserved but exposes a different contract; do not point the new frontend at it.

Every error uses `{ "error": { "code": "...", "message": "...", "details": {} } }`. IDs are strings, timestamps UTC ISO, amounts integer cents. Workspace and demo reviewer identity are configured server-side. No frontend provider keys.

## Workflow

1. Fetch `GET /api/health`, `GET /api/memory/active`, `GET /api/candidates`, and `GET /api/history`. Missing configuration yields health statuses plus explicit 503/404 responses on data endpoints; do not replace failures with synthetic results.
2. `POST /api/sources` with multipart `file` (PNG/JPEG, max 5 MiB/20 MP). Render `image_url`, `extracted_text`, `quotation`, and `proposed_text/proposed_scope`. Existing sources reload through `GET /api/sources/{source_id}`.
3. `POST /api/candidates` with `{source_id, text, scope, base_version_id}`. Scope has `kind` (`global`, `order`, `preference`) and nullable `order_id`, `customer_id`, `exception_id`.
4. `POST /api/candidates/{candidate_id}/runs` (no body) returns 202 `{run_id}`. Poll `GET /api/runs/{run_id}` every two seconds until terminal.
5. Run `selection` records have `case_id`, description, reasons, nullable semantic_score, frozen task. Join these to `cases` on `case_id`. Each case exposes `classification` and up to four executions with `side` (`baseline`/`candidate`), repetition 1/2, raw_responses, parsed attempt, tool_outcome, checks, error, latency and usage. A runtime denial does not erase the attempted action. A pending case is classified inconclusive until evidence completes.
6. Quarantine: `POST /api/candidates/{id}/quarantine` `{reason}`. Revision: `POST /api/candidates/{id}/revise` `{text,scope}`, returns a new staged candidate based on current active memory. Old evidence stays intact.
7. Approval: `POST /api/candidates/{id}/approve` `{run_id,reason}`. Approval and quarantine require a unique `Idempotency-Key` header; reuse the same key only when retrying the exact same operation. 409 means refresh/retest as appropriate. Approval returns the updated Candidate; then refresh active version/history.
8. Voice: `POST /api/runs/{run_id}/cases/{case_id}/audio` `{side,repetition}` returns `{audio_id,audio_url,transcript,cached}`. Use ordinary audio controls. Voice is optional and independent of admission.

Candidate states: staged/testing/eligible/quarantined/inconclusive/approved. Run states: queued/running/completed/failed/inconclusive. Admission is null while pending, otherwise eligible/quarantine/inconclusive. Always trust backend admission; no force approval.

All runs from this backend use `live: true` because evidence comes from actual configured provider calls. Frontend mock fixtures must show a persistent synthetic banner and never assert a live run. Lists include `truncated` and the latest 100 records. History lists only the active version ancestry, never unactivated prepared versions.

## Local teammate workflow

Frontend belongs to `feat/membrane-review-ui`. Backend belongs to `feat/membrane-backend`. Generate TypeScript types from this schema into frontend-owned files. Do not edit backend DTOs or root configuration. Use localhost port 5173 and proxy `/api` to 127.0.0.1:8000; the API binds locally.
